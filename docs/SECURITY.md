# TherapyBot security model — 2026-11-04

1. **Browser → localhost:** the HTTP server binds only to `127.0.0.1`, verifies Host and Origin, requires a per-process bearer capability for private GETs and JSON mutations, sets a restrictive CSP and offers no CORS permission. The capability arrives in a launch URL fragment, is moved into browser-tab session storage, and is rotated on vault unlock/lock (other tabs are revoked). It is never reflected in publicly fetched HTML. The private link appears in the console only with `--no-browser`. This mitigates ordinary cross-origin form, casual other-process access and DNS-rebinding attacks, but anyone obtaining the valid token or controlling the unlocked browser can act as the user.
2. **Server → model:** only explicit HTTP loopback endpoints are allowed, and redirects and inherited proxy settings are disabled. The model is given no filesystem, shell, internet, email or external tool authority. The separately operated model runtime could still log or transmit content; it must be inspected and configured independently.
3. **App → SQLite:** chat and journal bodies use AES-256-GCM with random 96-bit nonces, authenticated record ID/kind, passphrase-derived scrypt key and no app request logging. Record IDs, types and timestamps remain plaintext. The key stays in process memory while unlocked. This is not whole-disk encryption.
4. **Source index → model:** source summaries are reference data, not executable instructions. Prompt injection cannot be ruled out through prompting alone, so the model is never granted high-impact tools.
5. **Export → other storage:** JSON export is plaintext by design and user-initiated. Browser downloads, snapshots, external backups, SSD remanence, swap/pagefiles, malicious browser extensions and OS compromise are beyond this vault's protections. `PRAGMA secure_delete=ON` does not ensure forensic erasure.

No HIPAA compliance, clinical safety, offline efficacy, or penetration-test certification is claimed. Verify actual model outputs, process/network behavior, and browser security on the target host before using with consequential personal records. Never place private records in public GitHub issues, CI, screenshots or diagnostics.
